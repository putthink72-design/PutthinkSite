# 펏띵(Putthink) 웹사이트 — 수정 프롬프트

이 문서는 기존 `Putthink_Site_Cursor_Prompt.md`(사이트 최초 개발 프롬프트)를 이미 적용한 코드베이스에, **그 이후 확정된 비즈니스 로직 변경을 반영**하기 위한 수정 지시서입니다. 디자인 소스는 여전히 `putthink_site_mockup_v2.html`(최신본)이고, Data Room은 `data_room_mockup.html`입니다.

---

## 0. 무엇이, 왜 바뀌었는가 (배경 요약)

기존 프롬프트는 "무료 실행 9회 + 구독 시 3일 체험(일반) / 무료 실행 18회 + 7일 체험(초대)"이었습니다. 검토 과정에서 아래 두 가지 문제가 발견돼 구조를 다시 잡았습니다.

1. **초대 시 체험 기간을 늘려주는 방식은 "체험 어뷰징 우회 수단"이 됩니다.** 초대 링크는 횟수 제한이 없어서, 아무나 커뮤니티에 돌아다니는 초대 링크를 주워 체험만 반복해서 받을 수 있었습니다. → **구독 체험 기간 자체를 전원 폐지**하고, 차등은 오직 "무료 실행 횟수"에만 둡니다.
2. **초대한 사람에게 "무료 실행 크레딧"을 주는 보상은, 이미 구독 중인 사람에게는 사실상 쓸모가 없습니다**(무제한 이용 중이니까). 크레딧이 "구독을 쉬어야 쓸 수 있는 것"이 되면서 은연중에 해지를 유도하는 구조였습니다. → Apple의 **Promotional Offer**(기존/과거 구독자에게 다음 갱신 할인·무료를 적용하는 정식 기능, 해지 불필요)를 활용해, **구독 중인 초대자는 "다음 결제 1주 무료"**를 받도록 바꿨습니다. 1주는 어떤 요금제든 포기하는 금액이 신규 유료전환자 1명의 순매출보다 항상 작아서, 아무리 반복돼도 손해가 안 나는 구조입니다 — 그래서 **반복 횟수 제한이 필요 없습니다.**

## 1. 확정된 최종 비즈니스 로직 (이 표가 유일한 기준)

| 항목 | 값 |
|---|---|
| 일반(조직적) 다운로드 무료 실행 | **3회**, 카드 등록 없음 |
| 초대 링크로 다운로드 시 무료 실행 | **6회**(일반의 2배) |
| 구독 시작 시 무료체험 | **없음 — 전원 동일, 즉시 결제 시작** (일반/초대 구분 없음) |
| 요금제 | 월 $9.99 · 3개월 $24.99 · 6개월 $44.99 · 연 $74.99 |
| **초대한 사람 리워드 — 무료 티어(한 번도 구독 안 함)** | 친구가 구독 시작하는 순간 **무료 실행 +3회** 즉시 적립 |
| **초대한 사람 리워드 — 구독 중 또는 과거 구독 이력 있음** | 친구가 구독 시작하는 순간 **다음 결제일이 1주 무료**(Apple Promotional Offer, 해지 불필요, 자동 적용) |
| 초대 리워드 반복 제한 | **없음** — 위 계산상 아무리 반복돼도 순이익이라 자체 캡 불필요 |
| 무료 실행 어뷰징 방지 | 기기 단위(iOS Keychain, 삭제·재설치에도 유지) + 계정 단위(Sign in with Apple/Google + Supabase) 이중 체크, 최초 1회만 지급 |

**웹사이트 카피에서 절대 쓰면 안 되는 표현**: "무료체험 3일", "무료체험 7일", "체험판" — 이제 그 어떤 경로로도 구독 체험 기간은 존재하지 않습니다.

## 2. 페이지/섹션별 수정 지시

### 홈 히어로
- "다운로드 후 9회 무료" → **"다운로드 후 3회 무료"**로 전부 교체 (메타 디스크립션 포함)

### `/pricing`
- 무료 플랜 카드: "9회" → **"3회"**
- 헤드라인 "먼저 9번, 그냥 써보세요" → **"먼저 3번, 그냖 써보세요"**
- 서브카피에서 "3일 무료체험" 문구 완전 삭제 → **"다운로드하면 카드 등록 없이 3회를 무료로 쓸 수 있습니다. 다 쓰고 나서는 바로 구독으로 전환합니다."**
- 연간 플랜 배지 "3일 무료체험 · 가장 인기" → **"가장 인기"**만 남김
- 연간 플랜 CTA 버튼 "3일 무료로 시작" → **"연간 구독 시작"**

### Invite 섹션 (가장 크게 바뀐 곳)

**"보낸 사람" 카드**
```
제목: 구독 중이면 다음 결제 1주 무료 / 아니면 무료 실행 +3회
부제: 지금 상태가 무엇이든 받습니다
목록:
- 구독 중이거나 구독한 적 있으면: 친구가 결제를 시작하는 순간, 내 다음 결제일이 1주 뒤로 밀립니다(해당 기간 무료). 해지할 필요 없이 자동 적용됩니다.
- 아직 한 번도 구독 안 했다면: 무료 실행 크레딧 +3회가 즉시 쌓입니다.
- 제한 없이 반복: 매달 초대해도 매달 적용됩니다.
```

**"받은 사람" 카드**
```
제목: 무료 실행 6회로 시작
부제: 그냥 다운로드하면 3회, 초대 링크로 오면 2배
목록:
- 다운로드 즉시 6회 무료: 카드 등록 없이 바로 시작합니다.
- 같은 조건으로 계속: 다 쓰면 그때부터는 구독으로 넘어갑니다.
```

**섹션 서브카피**: "초대 링크로 들어오면 둘 다 원래보다 더 받습니다. 몇 명을 초대하든 계속 쌓이고, 초대 횟수 제한은 없습니다."

**"이렇게 반복해도 손해가 안 나는 이유" (개발 참고용, 화면에 안 띄워도 됨)**: 1주 무료의 가치는 어떤 요금제든 약 $1.4~2.3 수준인데, 이 리워드를 유발하는 신규 유료전환 1명의 순매출(Apple 수수료 15% 제외)은 최소 $8.5 이상입니다. 반복될 때마다 오히려 순이익이라 별도 지급 상한이 필요 없습니다 — 혹시 나중에 요금제가 바뀌어 이 부등식이 깨지면 그때 캡을 재검토하세요.

### `/data-room` (참고 — 이미 반영되어 있다면 스킵)
KPI 카드는 8개(4열 2행): 누적 다운로드 / MAU / 누적 전환율 / 최근 30일 전환율 / 누적 유료 전환자 / 활성 유료 구독자 / 유지율 / MRR. 국가별 테이블은 다운로드·전환율·누적 전환자·활성 구독자·유지율·MRR 6개 컬럼. 이미 `data_room_mockup.html`에 반영되어 있으니 코드가 이와 다르면 맞추세요.

## 3. Supabase 스키마 변경

```sql
-- profiles 테이블에 컬럼 추가
alter table profiles add column device_keychain_id text unique;  -- Keychain에 저장된 기기 식별 토큰
alter table profiles add column free_tier_claimed boolean not null default false;
alter table profiles add column free_tier_source text check (free_tier_source in ('organic','invited'));

-- 초대 리워드 지급 로그 (반복 제한은 없지만 감사 목적으로 전부 기록)
create table invite_rewards (
  id uuid primary key default gen_random_uuid(),
  inviter_id uuid references profiles(id) not null,
  invitee_id uuid references profiles(id) not null,
  reward_type text not null check (reward_type in ('credit_3','promo_offer_1week')),
  granted_at timestamptz default now()
);
```

- `free_runs_balance` 초기값 로직 수정: 일반 가입 `3`, `referred_by` 있으면 `9`
- `credit_ledger`의 `amount` 기본값 지급 로직에서 `+9` → **`+3`**로 수정(무료 티어 초대자 보상)
- Promotional Offer 지급은 크레딧 원장이 아니라 `invite_rewards`에 `reward_type='promo_offer_1week'`로 기록, 실제 Offer 서명·발급은 앱 쪽(App Store Server Notification 웹훅 → Edge Function → 서명된 offer를 다음 앱 실행 시 클라이언트에 전달)에서 처리 — 자세한 흐름은 앱 프롬프트(`Putthink_App_Development_Prompt.md`) 4장 참고
